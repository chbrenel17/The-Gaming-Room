# Software Design Document - The Gaming Room

## Overview
This project focuses on designing a scalable, multi-platform software solution for The Gaming Room. The goal was to expand the existing game, *Draw It or Lose It*, from a single platform to multiple operating systems while supporting multiple users and game sessions.

## Features
- Multi-user game support with teams and sessions
- Cross-platform compatibility (Windows, Linux, mobile)
- Scalable architecture for concurrent gameplay
- Efficient memory and storage management for image rendering

## Technologies Considered
- Linux-based server environments
- Cloud-based deployment options
- Distributed system architecture
- Network communication between clients and servers

## Reflection

The Gaming Room is a client that wanted to expand their game, *Draw It or Lose It*, beyond Android to support multiple platforms. The application needed to handle multiple players, teams, and game sessions while maintaining performance and reliability.

One thing I did well in developing this design document was organizing the system architecture and clearly explaining how different components would interact. I focused on making the design understandable while still addressing important concepts like scalability and performance.

Working through the design document was helpful because it required thinking through the system before implementation. It helped me consider factors such as memory usage, storage requirements, and how the application would perform across different platforms.

If I could revise one part of the document, I would add more detail to specific technology choices and implementation strategies. This would make the design more practical and closer to a real-world production system.

I interpreted the user’s needs by focusing on scalability and performance, especially since the application involves real-time gameplay with multiple users. Considering user needs is important because it ensures the system is not only functional but also efficient and user-friendly.

When designing the software, I broke the system into smaller components and analyzed how they interact. In the future, I would continue using this approach and incorporate more detailed architectural diagrams and technology comparisons to strengthen the design process.
